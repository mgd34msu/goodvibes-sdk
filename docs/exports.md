# Public exports

GoodVibes SDK exposes deliberate entrypoints. Code under repository
source folders is implementation, not public API.

## Facade package

`@pellux/goodvibes-sdk` is the consumer-facing facade. It composes the
source-of-truth workspace packages and SDK-owned platform/runtime modules.

Use the root package for normal daemon-connected client work:

```ts
import { createGoodVibesSdk } from '@pellux/goodvibes-sdk';
```

The package also exposes `@pellux/goodvibes-sdk/package.json` as metadata.

## Source-of-truth package facades

These subpaths expose source-of-truth workspace package outputs:

- `@pellux/goodvibes-sdk/contracts`
- `@pellux/goodvibes-sdk/contracts/node`
- `@pellux/goodvibes-sdk/contracts/operator-contract.json`
- `@pellux/goodvibes-sdk/contracts/operator-openapi.json`
- `@pellux/goodvibes-sdk/contracts/peer-contract.json`
- `@pellux/goodvibes-sdk/errors`
- `@pellux/goodvibes-sdk/daemon`
- `@pellux/goodvibes-sdk/operator`
- `@pellux/goodvibes-sdk/peer`
- `@pellux/goodvibes-sdk/transport-core`
- `@pellux/goodvibes-sdk/transport-http`
- `@pellux/goodvibes-sdk/transport-realtime`

`@pellux/goodvibes-sdk/transport-direct` is an SDK-owned facade over direct
transport helpers from `transport-core`; it is not backed by a separate
transport-direct sibling package.

See [Transports](./transports.md) for the canonical `transport-direct` facade
description.

## Embedding facade

`@pellux/goodvibes-sdk/embed` is a separate, narrower facade from the root
package. It is the frozen 1.0 SDK Embedding API for hosting a GoodVibes
session inside another application (`createEmbeddedSession`, `bootDaemon`,
and the permission-callback contract). It curates existing runtime machinery
rather than adding new engine surface, so its breaking changes are gated by
their own API Extractor report separate from the root package's. See
[Public Surface](./public-surface.md) for the full contract.

## Platform surfaces

Platform subpaths are intentionally listed in `packages/sdk/package.json`.
There is no catch-all platform contract. If a platform path is not listed in
package exports, it is private implementation.

Client-safe surfaces:

- `@pellux/goodvibes-sdk/auth`
- `@pellux/goodvibes-sdk/browser`
- `@pellux/goodvibes-sdk/browser/knowledge`
- `@pellux/goodvibes-sdk/browser/homeassistant`
- `@pellux/goodvibes-sdk/browser/agent`
- `@pellux/goodvibes-sdk/client-auth`
- `@pellux/goodvibes-sdk/events`
- `@pellux/goodvibes-sdk/events/<domain>` for the explicit public event domains documented in [Public Surface](./public-surface.md)
- `@pellux/goodvibes-sdk/observer`
- `@pellux/goodvibes-sdk/web`
- `@pellux/goodvibes-sdk/workers`
- `@pellux/goodvibes-sdk/react-native`
- `@pellux/goodvibes-sdk/expo`

Runtime-heavy surfaces live under `@pellux/goodvibes-sdk/platform/...`. There
are over ninety of these subpaths, spanning subsystems from provider routing
(`platform/providers`) and orchestration (`platform/orchestration`) to
device capabilities, email and calendar connectors, sandboxed exec, and the
curated `platform/runtime` namespace bundle. This document does not re-list
them, because a second copy of a ninety-entry table drifts from the real
export map the moment either copy is edited alone.

Pick the narrowest entrypoint that matches the runtime. Do not import from
workspace package source directories, `dist`, or unlisted deep paths in
application code.

See [Public Surface](./public-surface.md) for the complete, per-subpath table
with descriptions and stability levels; it is generated by hand against
`packages/sdk/package.json` and is the only place that list is maintained.

## Sibling-package deep subpaths

The source-of-truth sibling packages publish deep subpaths of their own, for example
`@pellux/goodvibes-contracts/generated/*`, `@pellux/goodvibes-contracts/zod-schemas/*`, and
`@pellux/goodvibes-contracts/node`; `@pellux/goodvibes-daemon-sdk/*` route helpers plus its
`relay-server`, `sessions`, `tasks`, and `telemetry-routes` modules;
`@pellux/goodvibes-transport-core/*` (including `direct`, `client-transport`, and `relay`);
`@pellux/goodvibes-transport-http/*` (auth, backoff, retry, SSE, and the contract client);
`@pellux/goodvibes-transport-realtime/*` (`domain-events`, `runtime-events`, `relay-transport`);
`@pellux/goodvibes-operator-sdk/client*` and `@pellux/goodvibes-peer-sdk/client*`; and
`@pellux/goodvibes-errors/daemon-error-contract`. These exist to compose the
`@pellux/goodvibes-sdk` facade and are not part of the supported consumer contract. Prefer the
matching `@pellux/goodvibes-sdk/...` subpath; the bare sibling deep paths may change without notice.
